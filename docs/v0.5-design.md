# v0.5 竞赛原生设计

v0.5 改变了工作流的优化目标：在保持真实性和提交安全所需证据严格的前提下，提高单位上下文与操作成本能够获得的比赛可靠性。

## Evidence Gate，而不是 Schema Gate

Deterministic check 继续严格检查官方输入身份、真实执行、代码/输出 provenance、result locator、review package/handoff freshness、最终 PDF/source binding 和非伪造原则。

模型广度、敏感性深度、图表密度和文字润色默认是 warning 或 suggestion；只有当它们暴露具体 P0，例如关键结论无证据或结果与代码不一致时才阻断。

Common artifact 的 review envelope 可选。正式批准保存在 decision log 及其自动派生 snapshot 中，减少重复字段。

## 上下文分离

仓库只保留一个主 Skill router，但区分 orchestrator、modeling、computation、validation、paper 和 delivery。跨职责使用四种 handoff。新 task 读取精简 handoff，而不是扫描完整 workspace。

Paper handoff 面向论文作者，包含 problem/model summary、verified results、claims、真实 limitation、主动识别的 `representation_candidates` 和按角色分类的官方材料；它有意排除 run/debug history。Model `scope` 与 contradicted/unsupported claim 不冒充 limitation，候选表达也不依赖已有 figure。Targeted review 后会沿轻量结构化 lineage 保留仍有效 P1。

## 有边界的 Review

Finding 使用 P0/P1/P2。只有 P0 可以产生 `revision_required`。第一次 full review 后，开放 P0 定义下一次 targeted re-review 的默认范围；新增 P1/P2 不会形成无限阻塞队列。

复核包与 review result 带有 package/upstream digest 和 task ref，使旧 review 不能静默验证已改变的计算。Digest 只绑定正式结果所需 canonical evidence，不绑定失败实验或完整日志。Targeted 包通过精简 `TARGETED_FINDINGS.json` 自包含原 P0。Computation handoff、复核包和 Delivery 源码选择共用一个严格 canonical resolver。它们增强 independence evidence，但不证明 reviewer 身份或正确性。

## 单一选定计算后端

MATLAB 在条件相同时优先，Python 是 fallback；auto 也可以因任务适配明显而直接选择 Python。MATLAB executable 按显式配置、PATH、macOS Applications 顺序检测；preferred 不可用可以 fallback，`required_backend` 不可用则报错。每个 official run 记录一个语言、选择理由、runtime、dependencies/toolboxes、entry point 和 source-tree snapshot。

正式任务默认只实现并运行一种后端。跨语言 parity 只有用户明确要求时才建立。数学模型和 result contract 保持 language-neutral。

## Snapshot 与 Scoped Revalidation

Accepted decision 自动生成 stage snapshot；`revision_requested` 会使对应 snapshot 失效。信任按阶段前缀传播：上游 stale 后，下游 snapshot 不再报告 trusted。

变化分为 `cosmetic`、`local`、`semantic`、`claim_changing` 和 `global`，避免多个文件变化就默认 full-workspace review。成本较低的 hard invariant 始终重查。

## Working 与 Finalizing

- `working` 用于快速建模、计算、debug 和修改，只严格维护真实性与必要 provenance。
- `finalizing` 用于冻结 claim-bearing results，要求 passed state、accepted decision/snapshot、fresh handoff、independent validation、paper/PDF QA 和 delivery binding。

`enforce` 在 working 中只能报告 `working_ready`，不代表正式批准；finalizing 中不能靠编辑 state 绕过上游 gate。

## 论文质量

Paper planning 以 claim 和 representation 为中心，而不是固定九层 schema。写作顺序是 verified results → claim selection → prose/equation/table/figure planning → representations → paper structure → LaTeX → rendered PDF QA。`paper_structure` 直接决定主体 section 及顺序；initializer 只生成可编辑 scaffold，不再按每问强制三小节。

LaTeX scaffold 使用克制的标题、公式、float、caption 和 booktabs/table 间距。Final QA 强调信息设计、caption、table、equation、页面密度、figure placement 和 PDF 可读性，不设置 hard figure/page minimum。参考一等奖论文仅提供摘要信息密度、claim-serving figures、结果解释和具体模型评价等 style prior；其章节、页数、图数、模型与当届格式不复制。Metadata 明确的官方论文模板优先采用/适配；规则说明文件不会仅因存在而阻断 generic scaffold，但正式合规保持未确认。Initializer 不提供可误入成品的通用标题或关键词。

## 兼容性

v0.4 迁移采用保守复制：升级兼容 contract、保留产物、从 working 开始，并把旧 run 标为 non-official。进入 finalizing 前必须用选定后端重新运行，并重建当前 handoff 和 review。
