# v0.5 contest-native design

v0.5 changes the optimization target of the workflow: maximize contest reliability per unit of context and operator effort, while keeping evidence that materially affects truth or submission safety strict.

## Evidence gates, not schema gates

Deterministic checks retain official-input identity, real execution, code/output provenance, result locators, review/package freshness, final PDF/source binding, and non-fabrication. Model breadth, sensitivity depth, chart density, and writing polish are warnings or suggestions unless they expose a concrete P0.

The common artifact review envelope is optional. Formal approval lives in the decision log and derived snapshot, reducing repeated fields.

## Context separation

The workflow keeps one Skill router but separates responsibilities and formal handoffs. New tasks read compact handoffs rather than scanning the workspace. The paper handoff is deliberately reader-facing and excludes run/debug history.

## Bounded review

Review severity is P0/P1/P2. Only P0 can produce `revision_required`. After the first full review, open P0 findings define the next targeted pass. Packages and results carry digests so a successful old review cannot silently validate changed computation.

## One selected computation backend

MATLAB is preferred on ties, Python is fallback, and automatic selection may choose Python directly. Each official run records one language, rationale, runtime, dependencies/toolboxes, and a source-tree snapshot. Cross-language parity is opt-in.

## Snapshots and scoped revalidation

Accepted decisions automatically generate stage snapshots. Trust is prefix-ordered: when one stage becomes stale, downstream snapshots are not reported as trusted. Changes are classified as cosmetic, local, semantic, claim-changing, or global to avoid default full-workspace review.

## Paper quality

Paper planning is claim-led rather than nine-layer-schema-led. The LaTeX scaffold uses flexible narrative sections, and final QA emphasizes information design, captions, tables, equations, layout, and PDF readability. There is no hard figure/page minimum.

## Compatibility

The v0.4 migration is copy-based and conservative. It upgrades contract versions and compatible shapes, preserves artifacts, starts in working mode, and marks old runs non-official. Finalizing requires a fresh selected-backend run and current handoffs/review.
